# 开发路线图

> 按阶段推进。每个阶段都应有可运行结果与明确验收条件。若仓库已有实现，先盘点后调整顺序，避免重复开发。

## M1 里程碑 — 最小可玩闭环（当前优先）
优先打通「修炼区 → 副本 → 战斗/拾取 → 撤离/死亡 → 统一结算 → 成长 → 再进入」的完整循环，技能/法力穿插开发、不阻塞。分 6 个小阶段：
1. `data/` 配置层（数值集中，铁律 #1）✅ 已完成
2. 场景骨架：修炼区 Hub + 副本 Dungeon + `change_scene_to_file` 切换 ✅ 已完成
3. 单局状态 RunManager + 临时/永久分离 + 统一结算（防重复/防负数）✅ 已完成
4. 副本内容：出生点 / 敌人 / 拾取 / 固定出口 / 死亡 ✅ 已完成（含敌人接触伤害）
5. 成长选项：丹药（M1 只做「淬体丹」提升攻击）✅ 已完成
6. 连续多局收尾：清场 / 防重复 / HUD / 结算反馈 ✅ 已完成（完整循环待手动实测）

> 原 Phase 0–6 仍按顺序推进；M1 是当前阶段的切分与优先级调整，不取消后续阶段。

## Phase 0 — 项目盘点与基线确认
- [x] 检查 Godot 版本、项目结构、主场景、输入映射与现有脚本。
- [x] 确认项目可启动；记录当前错误与缺失内容。
- [x] 阅读本仓库文档，列出“已有 / 缺失 / 有风险”的清单。
- [x] 提出最小化实施计划，等待用户确认涉及核心方向的变更。

**验收：** 有一份真实反映当前仓库的盘点报告；不做无必要重构。 ✅ 已完成（2026-10-11）

## Phase 1 — 玩家操作与基础战斗
- [x] WASD 移动、对角线归一化、最后方向记忆。
- [x] J 普攻。
- [x] 基础生命、受击、死亡逻辑。
- [x] 一个简单普通敌人。
- [x] 一个可测试的小型战斗场景。

**验收：** 玩家能移动、朝向正确、攻击能命中敌人；基本战斗可重复运行。 ✅ 已完成（2026-10-11）

## Phase 2 — 主动技能与法力
- [ ] 统一玩家法力资源管理。
- [ ] 持续自动恢复，进入副本时回满。
- [ ] 一个主动技能完整走通施放校验、扣蓝、冷却与效果。
- [ ] 显示法力与冷却。
- [ ] 为后续技能预留一致的扩展接口，不提前制作庞大框架。

**验收：** 法力不足、冷却中、技能未解锁时均不会产生施放副作用。

## Phase 3 — 副本临时收益与结算
- [ ] 临时资源与永久资源分离。
- [ ] 固定出口交互与成功撤离。
- [ ] 死亡失败。
- [ ] 统一且只能执行一次的结算流程。
- [ ] 失败普通资源暂按 50% 保留。
- [ ] 副本重开时清空局内状态。

**验收：** 成功全额带走；失败按原型比例结算；没有重复发放或跨局残留。

## Phase 4 — 敌人刷新与回程压力
- [ ] 以刷新区域管理普通敌人。
- [ ] 玩家远离并等待后允许有限重刷。
- [ ] 每个刷新点最多重刷一次（原型）。
- [ ] 重刷敌人不重复发放常规资源。
- [ ] 精英/首领不刷新；出口附近无刷新点。

**验收：** 回程仍有压力，但不能通过无限刷怪无限产出资源。

## Phase 5 — 修炼区与成长闭环
- [ ] 展示永久资源。
- [ ] 至少一个科技树节点可购买并影响实际数值。
- [ ] 先实现法力上限、恢复速度、技能消耗三类路线中的最小可验证版本。
- [ ] 至少一个境界/解锁占位流程；具体规则经用户确认后再扩展。

**验收：** 副本收益能转化为永久成长，成长效果能在下一局中观察到。

## Phase 6 — 垂直切片打磨
- [ ] 调整移动、攻击、受击和技能反馈。
- [ ] 补齐关键 UI 状态与错误提示。
- [ ] 做一次完整的成功撤离流程测试与失败流程测试。
- [ ] 收集试玩问题，优先修复手感和可读性问题。

**验收：** 能连续完成“进入副本—战斗—收集—撤离/失败—成长—再次进入”的完整循环。

## 暂不排入近期计划
- 完整灵根/法宝阵容与全部技能。
- 大型随机地图、完整剧情、奇遇与隐藏资源系统。
- 大规模美术资产制作与完整特效库。
- 最终经济平衡、复杂存档迁移、联网等。
