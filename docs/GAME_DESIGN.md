# 游戏设计文档（第一版基线）

> 状态说明：`已确认` 表示用户明确决定；`原型建议` 表示可以先用于测试但不是最终平衡；`待决定` 表示不得擅自当成最终设计。

## 1. 游戏定位
- 类型：2D 俯视角、主动操作型、修仙题材增量动作游戏。
- 核心体验：战斗手感、技能视觉成长、境界突破、科技树成长、副本探索与资源风险回报。
- 核心循环：进入副本 → 探索与战斗 → 收集临时收益 → 前往固定出口撤离或死亡失败 → 结算资源 → 回到修炼区成长 → 挑战更高层次副本。

## 2. 战斗操作（已确认）
- WASD：移动。
- 角色朝向采用“最后方向记忆”：最后一次方向输入决定朝向，松开后保持最后朝向。
- 技能默认根据角色当前朝向施放，不使用鼠标瞄准作为默认操作方式。
- J：普通攻击，不消耗法力。
- K、L、U、I、O：主动技能键，均消耗法力并具有独立冷却。
- 技能形状可以不同，例如直线、扇形、范围或投射物，但具体技能内容待设计。
- 技能键固定；不设计自由装备/替换技能的搭配系统。技能随境界逐步解锁。
- 开局只开放少量技能，不应从第一分钟就拥有完整流派。

## 3. 技能施放校验（已确认）
主动技能施放必须同时满足：
1. 该技能已解锁。
2. 技能冷却已结束。
3. 当前法力足够支付消耗。

任一条件不满足时：不执行技能、不扣除法力、不启动冷却。法力与冷却的校验和扣除应通过统一流程完成，避免技能间规则不一致。

## 4. 法力系统（规则已确认，数字为原型建议）
- 法力在战斗、移动和施放技能期间持续自动恢复。
- 法力不足时仍可移动并使用 J 普攻，不增加额外惩罚。
- 每次进入副本时，法力恢复至上限。
- 科技树可以提升法力上限、自动恢复速度、降低技能消耗。
- 建议第一版使用统一玩家资源模块管理法力，技能提供消耗与冷却配置。
- 原型测试起始值（需实测调整）：
  - 法力上限：100
  - 自动恢复：5 点/秒
  - 主动技能消耗测试范围：20–50
  - 示例：K=20、L=30、U=40、I=25、O=50。仅为占位测试数据，不是最终平衡。
- UI 至少显示法力条与主动技能冷却状态；法力不足时应有清晰但不过度打扰的反馈。

## 5. 属性、灵根与法宝
- 灵根属性决定核心机制倾向，法宝决定技能的表现方式或机制触发方式。
- 初步属性方向：
  - 火：伤害、爆发、灼烧等进攻机制。
  - 水：技能回转、循环与持续施压。
  - 木：恢复生命/法力或续航。
  - 土：防御、减伤或稳健作战。
- 同一属性科技树不因武器组合而改变；不同法宝组合需要带来可感知的玩法差异，不能只是换颜色或单纯加数字。
- **本项目第一版已确认：火灵根 + 刀类法宝（MVP）。** 其余流派后续扩展。

## 6. 境界与成长
- 境界突破带来阶段性的力量飞跃。
- 科技树提供持续、可选择的成长。
- 技能成长可分为：掌握 → 强化 → 机制蜕变。
- 机制蜕变的示意：火刃从单次伤害，成长为附加灼烧区域、积累火势或触发余烬爆炸。此为设计示例，不是已确定技能。
- 科技树第一版建议先验证三条法力相关路线：
  1. 灵海扩容：提高法力上限。
  2. 灵气周天：提高自动恢复速度。
  3. 法力精炼：降低主动技能消耗。
- **境界名称已确认：练气 → 筑基 → 金丹 → 元婴。** 所需修为、突破流程、科技树完整结构与具体节点效果：待决定（初版突破门槛占位数值见 `scripts/GameManager.gd`，后续迁至 `data/`）。

## 7. 副本规则（已确认）
### 进入与运行
- 副本承担探索、战斗与获取资源的功能。
- 每次进入副本时法力恢复至上限。
- 副本临时收益与永久资源分开存储；拾取只增加本次临时收益，不立即写入永久资源。
- 每次副本为独立运行：结束后清空本次临时收益与该次运行中的敌人/刷新状态。

### 撤离
- 只能到达固定出口后撤离，不支持任意地点随时撤离。
- 第一版只需一个固定出口；抵达后简单交互即可成功撤离，不做复杂读条或撤离道具。
- 出口始终可用，不要求先清空敌人或完成支线。
- 出口附近避免设置敌人刷新点。
- 成功撤离后带走本次全部收益。

### 死亡与失败
- 死亡会结束本次副本并进入结算；第一版不做复活点、尸体回收或消耗道具复活。
- 失败保留部分普通资源。第一版建议暂定保留 50% 的普通资源（修为、灵石），剩余部分损失；这个比例需经测试调整。
- 特殊材料失败时是否按相同比例保留：待决定。
- 短暂失败演出暂不纳入当前开发范围，可在后续添加；不得因此阻塞副本闭环。

### 敌人刷新
- 部分普通敌人可在玩家远离后重新刷新，以保持回程压力。
- 刷新按区域/刷新点管理，不让每个敌人独立实现一套刷新逻辑。
- 精英敌人与首领不刷新。
- 普通敌人每个刷新点最多重新生成一次（原型建议）。
- 重刷敌人不再提供常规资源奖励，防止无限刷取。
- 出口附近不放刷新点。
- 原型测试参数建议：离开区域约 800 像素、等待约 15 秒、最多重刷一次。数值必须结合地图尺寸、摄像机视野和实际体验调整。
- 刷新距离、等待时间与区域尺寸均为待测试参数，不是最终规则。

## 8. 资源循环（初步方案）
建议先使用四类资源：
- 修为：角色成长与境界进度。
- 灵石：硬通货，购买丹药、突破境界与通用修炼消耗。
- 丹药：成长消耗品，用灵石购买后服用，永久提升某项属性（攻击/生命/法力等）。M1 先做 1 种「淬体丹」（提升攻击），丹药定义集中 `data/`。
- 特殊材料：精英、首领或特殊探索点获得，用于关键突破或稀有节点。

资源用途与经济比例仍需结合境界和科技树继续设计。不要在没有明确用途时增加更多货币类型。

## 9. 第一版垂直切片目标
构建一个小型、完整、可反复验证的闭环：
1. 玩家可以 WASD 移动并记忆最后朝向。
2. J 普攻可命中敌人。
3. 至少一个主动技能可施放，正确校验法力与冷却。
4. 至少一种普通敌人能攻击玩家，玩家与敌人均有生命值和死亡处理。
5. 法力持续恢复，UI 能显示生命、法力和技能冷却。
6. 副本内资源只记为临时收益。
7. 玩家可回到固定出口撤离；死亡也能结束副本。
8. 结算按成功/失败规则处理资源。
9. 返回修炼区后能购买至少一个简单成长节点，成长效果可验证。
10. 再次进入副本时法力满值，临时收益与上一局状态已正确清空。

## 10. 明确不作为第一版前置条件的内容
- 所有属性/灵根与法宝组合。
- 大型技能库、技能自由装备系统。
- 复杂随机地图、剧情系统、奇遇系统、隐藏区域全套内容。
- 复杂撤离、尸体回收、复活和动态难度。
- 最终平衡数值与完整后期经济系统。
