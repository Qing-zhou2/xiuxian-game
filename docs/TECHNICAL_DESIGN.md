# 技术设计文档（实现指导，不是过度设计的许可）

## 1. 总原则
先检查现有项目，再决定如何落地。本文描述职责边界和建议，不要求为了符合示例而推翻已有可用架构。若项目尚未建立，可采用简单、可扩展的结构。

## 2. 建议的模块职责
- **Player**：接收移动输入、维护最后朝向、执行移动、请求普攻/技能。
- **PlayerResources（或等价组件）**：管理生命、法力上限、当前法力、自动恢复与资源变更信号。
- **Combat/Health**：统一处理伤害、受击、死亡与无效目标检查。
- **SkillController**：接收技能请求，检查解锁、冷却和法力；通过校验后扣蓝、启动冷却并执行效果。
- **SkillData/配置资源**：保存技能名称、消耗、冷却、范围/伤害等配置。具体数据格式应根据项目规模和 Godot 版本选择。
- **Enemy**：敌人移动/攻击/受击行为；通过统一伤害接口造成伤害。
- **DungeonRun/RunState**：管理本次副本临时收益、当前副本状态与结算状态。
- **Reward/Settlement**：集中处理成功撤离与死亡失败的结算，防止重复结算。
- **Progression**：管理永久资源、科技树与境界成长。
- **UI**：显示状态并发送用户操作请求；不应成为游戏规则的唯一存储位置。

这些可以是节点、资源、脚本或组合组件；不必机械地为每个名词新建一个系统。

## 3. 核心数据流
### 技能施放
输入 → 检查技能已解锁 → 检查冷却 → 检查法力 → 扣除法力 → 启动冷却 → 执行技能效果 → 更新 UI。

若任一前置检查失败，必须保证没有副作用：不扣蓝、不启动冷却、不生成攻击效果。

### 副本拾取与结算
副本拾取 → 写入本局临时收益 → 成功撤离/死亡 → 进入一次性结算流程 → 将可保留部分转入永久资源 → 清空临时收益 → 返回修炼区。

必须防止重复触发结算造成重复发放。建议使用明确的副本运行状态或已结算标记。

### 法力恢复
在统一资源模块中按经过时间恢复法力，不能由每个技能各自管理恢复。恢复后限制在 `0..最大法力` 范围内。进入副本时设置当前法力为最大法力。

## 4. 输入与朝向
- 使用 Godot Input Map 中的动作名，建议包括 `move_up`、`move_down`、`move_left`、`move_right`、`attack_primary`、`skill_k`、`skill_l`、`skill_u`、`skill_i`、`skill_o`。
- 键位具体配置要检查现有项目；若没有则建立映射。
- 朝向使用最后一次有效方向输入更新；停止移动后保留朝向。
- 技能默认使用当前朝向。个别技能可以有自己的攻击形状，但不要默认改成鼠标瞄准。
- 对角移动需归一化，避免速度比水平/垂直移动更快（若采用 8 向移动）。

> 当前实现说明：现有代码用 `Input.is_key_pressed(KEY_*)` 与 `_unhandled_input` 直接判键，尚未接入 Input Map。Phase 2 引入 K/L/U/I/O 技能键时一并建立 Input Map 动作名。

## 5. 伤害与生命
- 所有攻击尽量调用统一的受伤/伤害接口。
- 伤害系统需检查目标有效性、死亡状态及必要的无敌时间规则（无敌时间是否采用待设计）。
- 不要让每个技能用各自不同的方式扣敌人生命。
- 伤害数字、击中特效和音效可以逐步添加，不要在闭环未跑通前一次实现完整表现系统。

## 6. 副本状态与资源
- 本局临时收益与永久资源必须分开存储。
- 成功撤离与死亡失败都只能结算一次。
- 普通资源失败保留比例暂按 50% 原型测试；特殊材料规则待决定。
- 重刷普通敌人不重复提供常规资源奖励。
- 精英与首领不刷新。
- 副本退出后清理本局敌人、刷新状态和临时收益。
- 单局临时收益由 autoload `RunManager` 管理（`reset()` 进副本清空、`settle()` 只结算一次）；永久资源（灵石、丹药、境界、成长加成）由 `GameManager` 管理。
- 成长消耗品「丹药」为永久资源：灵石购买 → 服用 → 对应属性永久提升；丹药定义集中 `data/`。

## 7. UI 最低要求
第一版至少包含：
- 玩家生命显示。
- 玩家法力条（当前/最大值可选）。
- 主动技能冷却反馈。
- 法力不足或技能不可用的明确反馈。
- 本局临时收益显示。
- 撤离交互提示。
- 成功/失败结算面板。
- 修炼区永久资源显示与至少一个可购买成长节点。

UI 展示数据应从对应游戏系统读取，不要复制一份会逐渐不同步的游戏状态。

## 8. 测试建议
优先验证边界条件：
- 法力刚好足够、差 1 点、为 0。
- 技能冷却刚结束与仍剩少量时间。
- 未解锁技能不能施放。
- 无效施放不会扣蓝或启动冷却。
- 法力恢复不会超过上限。
- 连续触发撤离/死亡信号不会重复结算。
- 失败时普通资源保留比例正确。
- 副本重开后临时收益和敌人刷新状态清零。
- 重刷敌人不重复发放常规资源。
- 对角移动速度正确，松开方向后朝向保持。

## 9. 版本与兼容性
- 开工前读取项目的 `project.godot` 并确认 Godot 版本。
- 不使用未经确认的版本专属 API。
- 如果没有 Godot 可执行环境，至少进行静态检查并在汇报中明确说明未能运行验证。
