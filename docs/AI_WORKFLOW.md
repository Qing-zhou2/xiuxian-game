# Claude Code 工作流

## 每次开始任务
1. 阅读 `CLAUDE.md`。
2. 阅读与任务相关的设计/技术文档。
3. 检查相关文件和实际项目状态，不根据旧对话猜测仓库现状。
4. 判断任务是小型可逆工作，还是涉及核心玩法/架构的决策。

## 执行策略
- 小任务：简短说明计划后直接实施。
- 中型任务：先列出 3–6 个步骤，按步骤实现和验证。
- 大型任务：拆分成多个可独立运行的阶段，不要一次性生成大量代码。
- 涉及重大玩法选择、不可逆文件操作、架构大改或删除数据：先给出推荐及理由，等待用户确认。
- 如果仅缺少低风险细节，可采用最简单方案，并把假设写进开发日志。

## 代码改动约束
- 先读后改；尽量复用现有场景、脚本与资源。
- 一次任务只解决一个主要问题，避免无关重构。
- 不要只创建脚本却不接入场景或输入映射。
- 不要以“看起来合理”代替运行验证。
- 不要用注释假装功能已经实现。
- 不要为未来可能出现的需求提前建立复杂框架。
- 未经同意不添加大型插件或依赖。

## 验证与交付
每次任务结束时汇报：
1. **完成内容**
2. **修改文件**
3. **验证方式与结果**（区分实际运行与静态检查）
4. **未完成/已知问题**
5. **推荐的下一步**（只推荐最有价值的一步）

若无法运行 Godot，明确写出“未能实际运行验证”，并列出可执行的验证建议。
重要规则变更同步到相应文档；不要只在聊天中记录。
